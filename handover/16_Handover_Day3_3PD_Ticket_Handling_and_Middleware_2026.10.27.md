## 1. Overview and ticket types
- 3PD now covers **8 subsidiaries**, each on several marketplaces (Lazada, Shopee, TikTok Shop…). Most failures occur when **new SKUs go live** and are not fully set up in Hybris (SKU, price, stock); established flows rarely break. For SKU mismatches, explain simply which side is wrong and ask the subsidiary to check product/price/stock.
- Volume (TEC-TSP-02): 231 tickets in 2026 (~26/month): TH 55, PH 48, ID 28, AU 27, VN 26, SG 17, MY 17, NZ 13. In Jira they carry the 3PD PIC's label; a filter showed ~1,100 tickets overall.
- Tickets enter COEC and go to the **PIC 3PD** (a Tech member 100% on 3PD, with a backup), never to Merchandising. Typical titles: "[3PD] Stuck Order … TIKTOK", "Dummy stock …", "Cancelled orders no FI post", "MSA | NZL | Orders not found in MSA".
- Three kinds: **normal operation** (stuck orders, push from middleware to Hybris, editing customer name/address before push – CoE handles in the middleware portal and Hybris); **issue/incident** (integration/API/middleware failure – ticket the vendor e.g. Logicbroker, email parties, follow to closure); **development** (new product type needing new functions – PC ticket and development party).
- TEC-TSP-02 variants: V1 marketplace order not flowing (most common: "Stuck Order TIKTOK" ~11%, "Orders not found in MSA" ~6%); V2 status/cancellation/FI posting/GCRM (~3%); V3 order data mapping (amount, seller discount, freebie, delivery mode); V4 stock/price/product feed; others.

## 2. Working with the middleware
- Portal use (Logicbroker): failed orders show **Failed**; open for the error or scroll to Events; fix the cause first, then **Retry**. Warning: one order's price doubled on each Retry click – never click Retry repeatedly before knowing the cause. Ask for the API (Postman) collection to test on staging.
- "2) Logicbroker Common Issue" sorts errors into 4 levels: (1) subsidiary fixes (stock, delivery mode, inactive product); (2) COEC support (data entry breaking order sync); (3) COEC + Logicbroker (API issues); (4) RHQ/L2 (Bifrost-related). Common errors: *missing values for [warehouse]* (no stock – restock in Hybris, re-push, check delivery modes); *Product not found / UnknownIdentifierError* (inactive SKU – activate, sync, re-push); *No CountryCode / No region code mapping* (add ISO code to Custom Lookup).
- Biggest risk: **pushing orders before the cause is known** – double shipment or missing/zero FI posting; orders pushed to NERP can't be pulled back. Record the cause, get the subsidiary's confirmation nothing shipped, and an approved PC ticket even for one order.
- Middleware per country: Singapore **Intrepid**; AU has an eBay channel with direct API for product/stock; most others (PH, VN, ID, TH…) **Logicbroker**; MSA covers fraud and trade-in. Logicbroker generates the most tickets (oldest, most functions) but builds new functions at no charge; Intrepid is the most cooperative. Logicbroker calls the SamsungBifrost API to bring marketplace orders into Hybris. TC-03 says 4 middleware; the full list is pending from RHQ. **Name the middleware on every ticket before investigating.** CoE manages the middleware, not the marketplaces; portal access is requested by the Tech Lead.
- Escalation (TEC-TSP-02 §2.10): middleware not calling Hybris → middleware team via RHQ Platform (every 2 working days); Hybris code defect → development partner; marketplace refuses an update → subsidiary 3PD owner (every 4 working days); FI rejected → subsidiary finance.

## 3. Products on 3PD
- **Bundles (SPU):** a bundle SKU (e.g. 100 USD of A+B at 50/50) is sold on the marketplace; the middleware splits it into component lines by ratio; a 0 ratio makes the line a free gift (giveaway = true, linked to the parent entry). Missing setup turns the order type into YF10 (normal) instead of the bundle type. Logicbroker bundles are defined in Custom Lookup Bundle; set Installation = N to avoid "less than 3 breakout SKUs".
- **SC+ and services:** an external-service SKU loses its service through the middleware, so a **separate SKU** represents the service and activation codes are handled manually. Singapore has Virtual SC+ and Physical card (treated as a tangible product with a QR code); Malaysia handles SC+ pack codes its own way. SC+ on 3PD has its own session on 28/10.
- **Request template and PC tickets:** a template exists for 3PD product requests; SPU organisation is up to the VN team. Every direct Hybris production change needs an approved PC ticket (every push, re-send, status update or config change, even for one order; batches via TEC-ORD-05 / TEC-TSP-03; P0/P1 use a short emergency PC).
- **RNPL:** e.g. Fold 8 pre-order voucher for a discount; the digital voucher doesn't reach NERP, so the system sends an automatic email on voucher orders (tool name unclear). Details on 28/10.
- **Feeds:** a cronjob reads SKU data and per-warehouse stock and pushes to Logicbroker then the marketplace. Product feeds (descriptions, images) exist only for AU and NZ; others push stock only. E2E timings: product creation (AU, NZ only) and stock every **45 min**; orders and cancellations pulled every 40 min (50 per page); returns every 4 hours; inventory hourly. Marketplaces may apply an unattributed shipping discount, so the split ratio based on NERP prices won't fully match the marketplace price.

## 4. Handling process (from TEC-TSP-02, not in the recordings)
Intake (Level 1: identify flow and channel, set priority within 30 min – P2 for stuck marketplace orders, check master incidents, recent releases, post "do not re-push or cancel") → order table (Level 2: Backoffice orders, business process failed step, SO/DO/FI) → cause (trace by PO ID and time in logs, write the cause before any push) → fix (subsidiary confirms nothing shipped, approved PC ticket) → verify (Sub-Lead: expected status with SO, FI/GCRM results, no personal data) → missing info (ask once, ON HOLD SUBSIDIARY). Known errors: KE-01 stuck at order split (often missing delivery_mode_mapping), KE-02 404 order not found, KE-03 waiting for fraud result, KE-05 cancelled orders without/zero FI (mapping defect – don't re-send), KE-06 freebie missing in NERP. The same cause three times in a month opens a COE-PRB-01 problem record.
